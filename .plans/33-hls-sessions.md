# #33 HLS remux sessions: scratch, readiness, playlists, seek, proxy

## Summary

Play a Version over HLS without re-encoding. The play plan opens a remux session and returns a master playlist URL that carries the playback token. The api role authenticates every HLS request, maps the session to a transcoder in the Postgres registry, serves it in-process when it owns the transcoder, and proxies to the owner otherwise. The transcoder role runs one ffmpeg per session that copies the streams into fMP4 segments cut on the Item's segment timeline, in transcoder-local scratch. Playlists are built from the timeline and complete from the first byte. A request for an absent segment waits for its ready event up to 20 s, then answers 503. A seek is a request for a segment the running ffmpeg will not reach next: ffmpeg is killed and restarted at that segment's timeline timestamp; segments already in scratch are served without a restart. After 60 s without a request ffmpeg stops and the scratch is deleted. Live transcoding, subtitles and the admission cap are #34. Stored Versions are #35.

## Notes

- Workspace `/home/mia/mia-cx/pendia/.worktrees/hls`, branch `feat/33-hls-sessions`. Unattended run; decisions are recorded here.
- Segmentation. The hls muxer cuts on the first keyframe after a fixed grid (`hls_time`), so it cannot hit the timeline, whose boundaries are the keyframes nearest a 4 s target. The segment muxer takes explicit cut points. Measured on the fixture: `-f segment -segment_times ... -segment_format mp4 -individual_header_trailer 0 -segment_header_filename init.mp4` cuts exactly at 3, 6 and 9 s with a shared init. The full interior boundary list is passed on every run because the muxer indexes `segment_times` by the start number.
- Readiness. The segment muxer has no `temp_file` flag. It rewrites its own m3u8 segment list by temp file and rename after each segment closes (strace: close N, open list.tmp, rename, open N+1). The transcoder watches the run directory for that rename and marks the listed segments ready. That is the "read ffmpeg's own playlist" option from the #9 resolution; readiness never comes from the existence of a segment file.
- Timestamps. `-copyts -avoid_negative_ts disabled` on the outer context and `movflags=+frag_discont:avoid_negative_ts=disabled` on the inner mp4 muxer keep `tfdt` absolute, so a run restarted at 6 s writes a segment whose decode time is 6 s. Without both, the inner muxer rebases to zero. `-seek_timestamp 1 -ss <boundary>` seeks by actual pts; without it ffmpeg offsets by the file start time (-21 ms on this mkv) and lands on the previous keyframe. Cut times are passed floored to microseconds and the seek time ceiled, so a keyframe at the boundary is always inside the run.
- Each run writes to its own directory `scratch/<sessionId>/run-<k>/`, so a restart never truncates a segment another request is streaming. Init is identical across runs (verified byte for byte); the manager reads it into memory on the first ready segment and serves it from there.
- Remux copies the video Stream and the first audio Stream. Per-track audio renditions and subtitles follow the spec's Renditions section in #34 and #35.
- The transcoder never changes `session_registry.state`; the client lifecycle procedures own it. Idle stop kills ffmpeg and deletes scratch but keeps the session row live, so a paused player resumes with a plain segment request, which restarts ffmpeg at that segment.
- The transcoder registers a `transcoder_capabilities` row with `backends: []`; the startup trial is #34. A crashed transcoder leaves a stale row and an unreachable owner answers 503; a lease or heartbeat belongs with the admission cap in #34.
- Every HLS URL carries the token, as the issue says, so the transcoder's internal route verifies the same token when the api proxies to it. Cookie callers get a token URL too.
- `hls-parser` 0.16.1 (published 2026-03-29) is a dev dependency for playlist validation. hls.js needs a browser with Media Source Extensions, so browser playback is not part of the automated run; the test decodes init plus segments with ffprobe instead.
