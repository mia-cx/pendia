# #41 Jellyfin layer: playback and websocket

## Summary

Extend the Jellyfin layer from #40 with playback, progress and the websocket. `POST /Items/{id}/PlaybackInfo` translates the client's DeviceProfile into the engine's ClientProfile through one table, runs the core planner, and answers MediaSources whose flags say direct play, direct stream or transcode. A remux or transcode carries a TranscodingUrl in Jellyfin's `/videos/{id}/master.m3u8` shape with the playback token in its query. The `/Videos/{id}/stream` route serves the File, the `/Videos/{id}/...` HLS routes map onto the session HLS handler, and a subtitle route serves a text Stream as WebVTT. The three progress calls drive Pendia's session lifecycle, and the played and favourite routes write Pendia marks. `/socket` answers KeepAlive and pushes LibraryChanged and UserDataChanged, authenticated by header or by query.

Read contracts: CONTEXT.md, docs/spec/jellyfin-layer.md, docs/spec/playback.md, docs/spec/auth.md, docs/research/jellyfin-client-api-usage.md (Playback, Websocket), ADR 0004. Builds on `apps/server/src/jellyfin`, `playback/planning.ts`, `playback/progress.ts`, `playback/marks.ts`, `api/hls.ts` and `api/events.ts`.

- Playback tokens live five minutes, and Pendia's own player refreshes them. Jellyfin clients follow TranscodingUrl verbatim and cannot refresh, so the token in a Jellyfin URL lives 24 hours. It still dies when its session stops or its device signs out, because every use re-checks both.
- The playback token rides as `token` in the TranscodingUrl, the same name Pendia's HLS handler reads, so the session playlists' relative URIs carry it on unchanged. PlaySessionId names the session.
- Jellyfin clients put their own access token in stream and socket URLs as `ApiKey` or `api_key`. Pendia accepts it there, as #40 planned, but never writes the account token into a URL itself.
- Direct play means the engine's direct-play method: only SupportsDirectPlay is true. Remux sets SupportsDirectStream and SupportsTranscoding with a TranscodingUrl; transcode sets SupportsTranscoding with a TranscodingUrl. No path sets all three false, and PlaybackInfo still answers, because Findroid ignores the flags and plays `stream?static=true`.
- `/Videos/{id}/stream` serves the File whatever the profile said, as Jellyfin does for `static=true`. It still needs a credential and the view and play permissions.
- DeviceProfile translation reads only HLS TranscodingProfiles, since HLS is the one streaming protocol Pendia serves. CodecProfiles with ApplyConditions are skipped: they hold only in cases the engine cannot see, such as anamorphic video. A codec without an AudioChannels cap takes eight channels.
