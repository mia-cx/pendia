# job-lease: #87 job leases, #65 scan-status indexes, #72 retryAfter flake

## Summary

A claimed job stays `running` forever when its holder dies (#87). Each claim now writes a fresh `claim_token` and a `lease_expires_at`. The holder renews the lease on a timer while its handler runs. A claim takes expired running jobs back as a new attempt, and a job that runs out of attempts that way fails with a lease error. Complete, fail and renew match the claim token, so an old holder's late answer changes nothing.

The same migration adds the two partial expression indexes that `libraryScanStatus` needs (#65).

The `retryAfter` test stores a whole-second `expiresAt`, so the `Math.ceil` bound cannot reach 301 (#72).

## Notes

- Test Postgres runs on 127.0.0.1:55574, not 55564: RootlessKit reported 55564 in use with nothing listening on it.
- `claim_token` is `uuid not null default gen_random_uuid()`, so the type is never null and existing rows backfill. `lease_expires_at` is `timestamptz not null default now()`. The migration gives rows running at migration time one 60-second lease, so a previous-release worker still running one is not doubled at once; after that the next claim takes them back.
- Only running jobs with a live lease count toward a concurrency key. Otherwise an expired job would block its own reclaim.
- Reclaiming a job records `leaseExpiredError` ("Job lease expired before its holder finished.") as its error, the way a retried failure keeps its error.
- The watcher already posts a heartbeat every poll interval during a scan. That heartbeat now carries the job id and claim token and renews the lease; a 409 answer means the watcher lost the job.
- A watcher report must carry the holding claim token before anything else happens. A report without a readable token answers 400 and leaves the job running, since its lease recovers it. A report with the right token but a malformed body still fails the job, as before.
- The watcher protocol changed from `attempts` to `claimToken` in the claim and the report. The watcher and the api ship from the same release.
- Pullfrog review of e0f907a found two real P1s, both fixed in 0a724ce with regressions. `renew` now runs under the claim lock and refuses an expired lease, so a renewal cannot revive a lease that a claim already counted as free. `finishJob` renews with the report's token after the body arrives and writes under `hold`, so a report whose claim was taken mid-upload answers 409 and writes nothing.
